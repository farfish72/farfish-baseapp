# FarFISH Design System Implementation

This review covers the implementation of the FarFISH design system, converting scattered button styles into a single-source-of-truth Button component, establishing design tokens, and migrating all button usage across the codebase.

The implementation consolidates visual styling under a new `Button` component with 5 variants (outline, primary, secondary, danger, ghost), extracts design tokens into a TypeScript module, and migrates 4 components to use the new system. The default outline variant follows the user's specification: `#181a20` background with a 2px teal (`#00d4c4`) border.

**Watch for:** (confirmed) Missing hover state on secondary variant — the hover changes background but doesn't make the border change visible. (likely) globals.css still contains generic `button:disabled` style that may conflict with the Button component's disabled state. (confirmed) Documentation correctly describes all 5 variants and includes comprehensive migration examples.

**Verdict**: APPROVED

## High-level view

The Button component implements all 5 variants with correct styling — the default outline variant uses `bg-[#181a20]` with `border-2 border-[#00d4c4]` as specified. The component uses React.forwardRef, supports loading states with a spinner, and includes proper focus rings for accessibility.

Design tokens export colors, spacing, radius, typography, and shadows from `design-tokens.ts`, with values that match the CSS variables in globals.css. The tokens provide a type-safe import path for components that need inline styles or CSS-in-JS.

The globals.css file was cleaned to remove generic `button { }` and `button:hover:not(:disabled)` blocks, leaving only `button:disabled` with reduced opacity. A reference comment points to the Button component as the new single source of truth.

Four components were migrated: StakeModal, UnstakeModal, OnboardingModal, and WalletConnection. All imports are correct (`import Button from './ui/Button'` or `'./ui/Button'`), and variant choices match intent — primary for confirm actions, secondary for cancel, danger for destructive operations like disconnect/unstake, and outline for selections.

The README documents all variants with code examples, describes sizes (sm, md, lg), covers special states (loading, animated, disabled), and includes a migration guide showing before/after comparisons.

## Button component structure and variants

The Button component lives in `app/components/ui/Button.tsx` and uses React.forwardRef to support ref forwarding. It accepts `variant`, `size`, `loading`, `animated`, `disabled`, and standard HTMLButtonElement props.

The 5 variants are:

- **outline** (default): `bg-[#181a20] border-2 border-[#00d4c4]` — matches the user's spec exactly. Hover adds `bg-[#20232b]` and teal glow shadow.
- **primary**: `bg-[#00d4c4] border-2 border-[#00d4c4] text-black` — filled teal button for CTAs.
- **secondary**: `bg-[#20232b] border-2 border-[#848e9c]` — gray border on raised surface. Hover changes border to `white/50`.
- **danger**: `bg-red-500 border-2 border-red-500` — red background for destructive actions.
- **ghost**: `bg-transparent border-2 border-transparent text-white/70` — minimal button with no visible border.

All variants include `border-2` as required. The component applies a base class with `rounded-xl`, `transition-all duration-300`, focus rings (`focus:ring-2 focus:ring-[#00d4c4]`), and disabled state (`disabled:opacity-50 disabled:cursor-not-allowed`).

Loading state renders a spinning border element before the children and sets `disabled={disabled || loading}` to prevent interaction during async operations.

```tsx
{loading && (
  <span className="border-2 border-current border-t-transparent rounded-full animate-spin inline-block w-4 h-4 mr-2" />
)}
```

The secondary variant hover state changes background to `bg-[#20232b]`, which is the same as the base background, making the hover background change invisible. Only the border color shift to `white/50` provides hover feedback. This might be too subtle for users who rely on background change as the primary hover indicator.

## Design tokens module

The design tokens are exported from `app/styles/design-tokens.ts` as frozen objects with `as const` assertions for type safety. The module exports `colors`, `spacing`, `radius`, `typography`, and `shadows` — values match the CSS variables in globals.css. A JSDoc comment points back to globals.css as the canonical source.

## globals.css cleanup

The generic `button { }` and `button:hover:not(:disabled)` blocks were removed from globals.css. The file now contains only `button:disabled` with `cursor: not-allowed; opacity: 0.6;`. This rule reduces opacity to 0.6, while the Button component sets `disabled:opacity-50`. The two will compound (0.6 * 0.5 = 0.3 effective opacity), though in practice the Button component's Tailwind class will override the global rule due to specificity. A reference comment points to the Button component as the new single source of truth.

## Migration consistency across components

Four components were migrated:

**StakeModal.tsx**: Uses `variant="outline"` for close button, `variant="secondary"` for Cancel, and `variant="primary"` for the main Stake action. Category selection buttons toggle between `primary` (selected) and `outline` (unselected).

**UnstakeModal.tsx**: Uses the same pattern — `outline` for close, `secondary` for cancel, `primary` for confirm (Unstake).

**OnboardingModal.tsx**: Uses `variant="secondary"` for "Skip Tutorial" and `variant="primary"` for "Continue" / "Get Started".

**WalletConnection.tsx**: Uses `variant="danger"` for "Disconnect Your Wallet" (destructive action) and `variant="outline"` for "Connect Your Wallet".

All imports use relative paths correctly (`import Button from './ui/Button'`). All variant choices are semantically correct. No functional behavior was changed — the migration was purely a styling refactor.
